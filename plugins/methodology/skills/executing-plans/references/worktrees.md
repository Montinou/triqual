## Worktrees

A worktree for the plan's run as a whole is created only when your human partner explicitly asks for one, in this conversation or in their instruction files; the task worktrees of Parallel tasks are not that request and need none (`task-open --worktree` makes them) and neither are phase worktrees (`stack.mjs phase` makes them). Without that request you work in place and do not stop to ask; at most mention once that one is available.

1. **Detect existing isolation first:** `git rev-parse --path-format=absolute --git-dir --git-common-dir`. Two different paths (and `git rev-parse --show-superproject-working-tree` printing nothing, so it is not a submodule) mean you are already in a linked worktree: the plan's scripts run from the main checkout and refuse it (exit 3, `run from the main checkout`), so a plan is not run inside it. Create no other worktree: run the plan from the repository's main checkout, or, to keep the run apart from that checkout, in a clone of its own (see Initiatives: one clone per running plan).
2. **Native tool:** a native worktree tool of the harness (such as `EnterWorktree`, a `/worktree` command, a `--worktree` flag) makes a linked worktree, which the plan's scripts refuse, so it is not used for the plan's run.
3. **Own clone:** to keep the run apart from the main checkout, make a clone of the repository for it, in the directory your instructions name, and run the plan from that clone's main checkout (see Initiatives: one clone per running plan). A sandbox denial means you work in place and say so.
4. **Branch name:** never exactly the plan's `**Branch prefix:**` (use `wt/<prefix>`, or a detached HEAD): `node scripts/stack.mjs init PLAN_FILE` exits 3 on a branch with the prefix's own name.
5. **Clean baseline:** in a fresh worktree, install dependencies the way the project does (its manifest or lockfile says how), each command plain and on its own, then run the project's check before Task 1. Failures are reported to your human partner, who decides whether to proceed; later failures are then ambiguous otherwise.
6. **Cleanup:** whoever creates a worktree removes it when the work lands or is dropped (methodology:finishing-branch, Step 7).

## SSH remotes

`node scripts/stack.mjs` treats a remote as a GitHub remote when its URL is `https://github.com/<o>/<r>`, an `ssh://` URL with user `git` and host `github.com`, or `git@github.com:<o>/<r>` (an optional `.git` and a trailing slash are fine), or an SSH alias of `github.com`: `git@github.com-work:<o>/<r>`, or an `ssh://` URL with user `git`, host `github.com-<x>`, an optional `:<port>` and the path `/<o>/<r>`. The alias is the `Host github.com-<x>` entry of `~/.ssh/config` that picks an account's key (`HostName github.com`, `IdentityFile ...`).

**The rule.** The alias is the only host name that is recognised, and only because it still points at `github.com` and `gh repo view <owner>/<repo>` confirms it: `init` takes the repository from the URL's path and asks gh about it, so the check uses gh's own login, not the SSH key. If the check fails, the stack is local and `reason` carries gh's message.

**Why such a remote takes the `prs` layout.** `gh stack` pushes and talks to GitHub through the remote's URL and does not go through the alias. So any plan on an alias remote, linear or forest, is the `prs` layout: a v2 state, `git push --set-upstream <remote> <branch>` (which uses the alias's key) and `gh pr create --repo <owner>/<repo> --draft --base <parent>` (which uses gh's login), no `gh stack` call and no fetch. A linear plan then gets one independent PR per phase, each against the previous phase's branch (the first against the trunk), and merges parents first, as in `forest.md`. The three plain forms keep the `stack` layout and the v1 state.

**A state that already exists.** The alias only decides the layout of a new state. Re-running `init` on an existing state prints it and changes nothing, so a plan started before the alias was recognised resumes on its v1 state; a state is never rewritten to the other layout. `init` still exits 3 when a forest plan meets a v1 state (delete the state file and run `init` again). `mode github` refuses a v1 state on an alias remote (exit 3, "SSH alias"), because `gh stack` cannot use the alias: such a plan stays local, or delete the state file and run `init` again for the `prs` layout.

**Why other alias names stay local.** A host such as `gitlab.com-work`, `git.example.invalid` or `github.company.internal` is not known to be GitHub: its URL says nothing about which service, owner or repository it reaches, so guessing would push phase branches somewhere the PRs cannot follow. Only the `github.com-` prefix is read as GitHub. For any other host the stack stays in local mode (branches, no PRs), as for a non-GitHub remote; to publish from one, point a remote at one of the recognised forms, for example `git remote add gh git@github.com-work:<o>/<r>.git` and `--remote gh`.

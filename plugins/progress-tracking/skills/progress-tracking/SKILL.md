# Strict progress tracking

Two files, always up to date: the project's memory between sessions. The SessionStart hook injects them into every
session; whatever is not in them is lost.

| File | What it is | Shape |
|---|---|---|
| `progress.md` | Log of what was done | Append-only, one entry per task, newest **on top** |
| `status.md` | Snapshot of the overall state | Edited in place; never accumulates history |

They live at the repo root (committed mode) or in `.git/methodology/` (local mode); in store mode they are rows in the local database, with no files. Never guess paths:
`triqual tasks paths --json` prints `mode`, `progress`, `status`, `plansDir` and `specsDir`; outside an opted-in repo it
prints `"optedIn": false` and exits 0. Both carry `notOptedInMessage` and `localHookLines`. Without `triqual` on PATH, run
`node "${CLAUDE_PLUGIN_ROOT}/cli/tasks.mjs" <subcommand> …` instead.

## The rule

**A task is not finished until its entry is in `progress.md` and `status.md` reflects the new state, in the same
commit that closes it.** Local mode commits neither file: write both before that commit. No exceptions for size:
a one-line fix is a task too.

What counts as a task:
- a plan task (each one, not the whole plan)
- a review fix round, or the review itself when it produces decisions
- a rollout operation: migration, deploy, env var, secret rotation
- any change the user asked for, code or not (config, docs, infrastructure)

A task that does not end in a commit (a production operation, say) still gets its entry. In committed mode commit it
on its own: the `pre-commit` lets through a commit of tracking files only, but a staged ledger must still pass
`triqual tasks check --staged`.

## Entry format

```markdown
## YYYY-MM-DD — <short task title>
- **Stage/task:** <e.g. Plan x · T3> (or "off-plan")
- **Done:** <what changed and why, 1-3 lines>
- **Files:** <main paths>
- **Verification:** <commands run and the REAL result, e.g. `npm test` 390/390>
- **Commit:** <short sha, or "this commit">
- **Next:** <next concrete step>
```

- Insert it under the file header, above the previous entry.
- **Honest verification:** write down a failed test, a skipped step or anything left untested.
- **Immutable:** a committed entry is never edited. If it was wrong, add a new entry that corrects it.
- **Absolute dates** always.

## When `status.md` changes

With each task (the same commit in committed mode), edit whatever changed among:
- **Last updated** (date + what changed): always
- stage and status in the plan table; current task
- production / environment (deploys, migrations, env vars)
- repo health (tests, branch, sync)
- blockers, risks and next steps

Leave unchanged sections alone, and never rewrite `status.md` whole: the **Active plan** section between
`<!-- tasks:start -->` and `<!-- tasks:end -->` is generated by `triqual tasks`, never edited by hand.

## Task ledger

Each plan has one ledger, `<plansDir>/<plan name>.tasks.json`, rendered into the Active plan section. The plan must
sit directly in `plansDir`. Move tasks only through `triqual tasks`; never edit a `*.tasks.json` or the generated section
by hand.

| When | Command |
|---|---|
| Plan written | `triqual tasks init <plan.md> [--spec <path>]` (re-run after editing the plan: it reconciles) |
| Starting a task (its deps must be done or dropped) | `triqual tasks start T<N>` |
| Implementation handed to review | `triqual tasks review T<N>` |
| Review asked for changes | `triqual tasks rework T<N>` |
| Task committed and accepted | `triqual tasks done T<N> --commit <sha>` (any revision, e.g. `HEAD`) |
| Cannot go on | `triqual tasks block T<N> "<reason>"` (`start` resumes it) |
| No longer needed | `triqual tasks drop T<N> "<reason>"` (`restore` brings it back as pending) |
| Done task needs more work | `triqual tasks reopen T<N> "<reason>"` |
| Plan heading renamed | `triqual tasks retitle T<N> "<title>"` |
| End of the plan only (exits 2 while a task is unfinished) | `triqual tasks close` |

With several active ledgers add `--plan <plan.md|ledger>`. Also: `triqual tasks status [--json]`, `triqual tasks next`,
`triqual tasks check` (drift between ledger, plan and `status.md`), `triqual tasks render` (rewrites the generated section).
`check` does not compare a pending task's role with the plan until `triqual tasks init` reconciles it.
Exit codes: 0 ok, 1 `check` found drift, 2 invalid transition, bad arguments, ambiguous ledger or not opted in.
Repeating a transition exits 0 and changes nothing (safe after a compaction); `done` on a done task with a
different sha exits 2 (`reopen` first). `done` after `reopen` replaces the recorded sha: when rewritten
history leaves one unresolved (`check`), run `reopen T<N> "<why>"`, then `done T<N> --commit <new>`. Exit 3 comes
only from the `triqual` shim (plugin not installed).

**Bookkeeping (spec §6.3):** `done --commit` records a sha that already exists, so a transition's ledger and
`status.md` changes ride in the **next** commit (usually the next task's), or at the end of a plan in the **closing
commit**, which carries its own closing entry. **Committed mode: the next commit stages every dirty
`docs/plans/*.tasks.json` together with `status.md` (and `progress.md`).** Left dirty on their own, ledgers never
trip the Stop hook or the `pre-commit`, so a turn may end between tasks. Local mode: `triqual tasks` writes both files in
place and nothing is staged.

If `triqual tasks check --staged` blocks a commit: for a stale section run `triqual tasks render`, then `git add status.md`;
for `plan … is not in the index`, stage the plan with its ledger (the check reads both from the index).

## Local mode

For repos shared with a team or a client, where the log, `.githooks/` and a `CLAUDE.md` section must not be
committed: `triqual progress-init --local`. Files live in `<git-common-dir>/methodology/` (usually `.git/methodology/`):
`progress.md`, `status.md`, `plans/`, `specs/` (take the dirs from `triqual tasks paths --json`, never `docs/`). Claude
Code refuses agent file writes there, so draft in the OS temp dir and land it with `triqual tracking write`: an entry with
`triqual tracking write entry <draft>`, also `status`, `spec` and `plan`. Gates, hookless repos, the allow rule:
[references/local-mode.md](references/local-mode.md). `triqual progress-init --local --remove` permanently deletes that
directory (log, plans and specs, which no commit holds): always confirm with the user first.

If `progress.md` exists in both roots, committed mode wins.

## Store mode

For a repository whose history must carry no tracking: `triqual progress-init --store` keeps the entries, status and
ledgers in a local database; no tracking file is created, staged or committed. Land an entry with
`triqual tracking add <draft>` before its commit (`--no-commit` when the task ends without one), read the status with
`triqual tracking status`, change a section with `triqual tracking status set --section <heading> <draft>`, read the
history with `triqual tracking log`. All the rules: [references/store-mode.md](references/store-mode.md).

## With subagents and plans

- **The implementer writes its task's entry**; in committed mode it goes in the same commit (the `pre-commit`
  demands it), which also stages every dirty ledger with `status.md`. Put both rules in every implementer's and
  fixer's brief.
- The coordinator owns the ledger: `start` before dispatching, `review` when the implementer reports, `rework` or
  `done --commit` after the review. Subagents do not run transitions.
- Reviewers write no entries; the coordinator logs a review's findings, decisions and rulings as its own entry.
- Parallel subagents in one tree each add their entry on top; on a conflict keep both entries.
- Closing a stage or plan: the coordinator adds a closing entry, runs `triqual tasks close`, updates the stage table.

## What enforces it

- **git `pre-commit`** (installed by `/progress-tracking:progress-init`). Committed mode: non-tracking changes need
  `progress.md` and `status.md` staged; a staged ledger runs `triqual tasks check --staged`. Local mode: see above.
  Merges, cherry-picks, reverts and rebases pass. **Never `--no-verify`.**
- **Stop hook:** a turn with uncommitted work does not end unless `progress.md` records it (committed: among the
  changes; local: changed since the last gated commit, or, without hooks, newer than the last commit). If it blocks,
  write the entry even if the task is still in progress: "Done" says how far it got, "Next" what is left. It
  blocks once per change set: the same unrecorded changes pass the session's next stop, a new change blocks
  again, and a gated commit still demands the entry.
- **Store mode:** the store `pre-commit` demands a pending entry of this worktree and the Stop hook blocks without one;
  a store that cannot be read fails closed, naming `triqual tracking restore`.
- **SessionStart hook:** injects `status.md`, the latest entry and one line per active plan.

The hooks act only in opted-in repos: store mode (the `triqual.tracking=store` git config marker, which wins), or `progress.md` in either root.
